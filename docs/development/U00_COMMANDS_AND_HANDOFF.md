## Canonical commands

Run from the module root in PowerShell:

```powershell
moon info
moon fmt
moon test
moon test --target native
moon test --target wasm
moon test --target wasm-gc
moon test --target js
moon run tools/unicode-gen -- check --data unicode/data/16.0.0
moon run tools/unicode-gen -- generate --data unicode/data/16.0.0
moon run tools/unicode-gen -- import-tests --data unicode/data/16.0.0
```

The preferred target is native. The three generator command names and argument
forms are reserved now. In U-00 every well-formed request prints the command,
data path and an explicit unavailable diagnostic, then fails via core `panic`.
Invalid arguments print usage and fail. This is an unconditional fail-closed
scaffold: it does not inspect the filesystem or claim a supplied directory was
verified. It fails with missing data and also with an existing directory.
U-01 adds actual manifest/hash verification, U-02 parsing, and later cards add
generation, comparison and conformance import. There are no network calls in
the generator or tests.

The exact missing-data command above was run with
`unicode/data/16.0.0` absent (`Test-Path -LiteralPath unicode/data/16.0.0`
returned `False`). It printed the U-00 diagnostic and exited `-1073740791` on
native Windows, as expected. The panic stack trace is part of this temporary
stub; a nonzero status alone is insufficient to pass the CLI contract test.

```powershell
foreach ($targetName in @('native', 'wasm', 'wasm-gc', 'js')) {
    & ./tools/unicode-gen/test-cli.ps1 -Target $targetName

```

For each target the script invokes `moon run tools/unicode-gen --target
<target> -- <arguments>` with `check --data unicode/data/16.0.0`,
`generate --data unicode/data/16.0.0`, `import-tests --data
unicode/data/16.0.0`, and `check`. It asserts both nonzero exit and the matching
diagnostic, so compilation/runner failures cannot silently satisfy the test.

Unit tests exercise all three reserved commands, seven invalid argument
shapes, and executable-prefix handling. The first implementation failed to
compile because a match guard began on a new line; this was corrected. Initial
CLI integration on JS exposed core/env's untrimmed Node `process.argv` (two
prefix entries rather than one). This was fixed with target-specific prefix
handling and regression tests. Duplicate conditional test names produced a
warning, then were renamed. The final test runs are warning-free.

Additional inspection used `Get-Content`, `Get-ChildItem`, `rg --files`,

## CI contract and acceptance

The GitHub Actions workflow uses four independent Windows jobs with
`fail-fast: false`, Node 24.11.1 and the existing MoonBit compiler version
`0.10.9+6e6c44045`. Each job checks interfaces/formatting, runs its exact target
test command and the CLI process checks, and always writes its setup/test/CLI
outcomes to the job summary. There is no `continue-on-error` or runner fallback.
Setup or runner failure leaves a failed job; skipped tests are unverified.

- Architecture package skeleton and empty test/benchmark layout: complete.
- Native baseline: passed locally.
- wasm, wasm-gc and js baseline: each passed locally; none skipped.
- Canonical generator commands with missing-data failure: verified locally.
- CI target reporting: configured; remote GitHub execution is **unverified**.
